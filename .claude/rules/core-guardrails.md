# Core — 가드레일 (⛔ STOP)

**구현·기본값 변경·커밋 전에 반드시 멈춰야 하는 것**만 모았다. 여기 걸리면 다른 어떤 규칙·워크플로보다 먼저 중단하고 사용자에게 묻는다.

작업을 **어떤 순서로** 진행하는지(트랙 1개 선택 → 게이트 4개 통과)는 `core-workflow.md`가 담당한다.

**형제 규칙:** `core-guardrails.md` · `core-workflow.md` · `core-scope.md` · `core-followup.md` · `core-tools.md` · `harness-map.md`(슬롯)
경로·명령·옵션은 `harness-map.md`가 SSOT · Git 브랜치·커밋·PR 규칙은 `core-workflow-git.md`
스택 팩(Java·Spring)을 쓰면: `spring-boot-java.md`

## ⛔ STOP (모든 규칙보다 우선)

구현·기본값 변경·커밋 전 확인. **위반 시 중단·사용자 질문.**

### 0. 수정 범위 — `baro-ai/` 밖 금지

이 하네스(`.claude/`)는 5인 공용 모노레포(`baro-farm-be`)의 **저장소 루트**에 있지만, 규칙 본문·워크플로는 여전히 **`baro-ai/` 작업 전제**다(2026-09-04 기준 다른 모듈엔 아직 하네스가 없음 — 경위는 `harness-map.md` "이 프로젝트 특이사항").

1. **참조·조사는 자유** — 다른 모듈(`baro-order`, `baro-payment`, `baro-common` 등)의 코드·문서를 읽고, baro-ai와의 연동(Feign·Kafka 이벤트 등)을 파악하는 건 언제든 한다.
2. **쓰기(파일 생성·수정)는 `baro-ai/`(+ 하네스 자체인 `.claude/`)로 제한** — 그 밖 경로(다른 모듈, 저장소 루트 문서·설정 등)를 고쳐야 하는 상황이면 **왜 필요한지 짧게 설명하고 사용자에게 먼저 확인**한다. 조용히 진행하지 않는다.
3. **결정론적 백스톱** — `.claude/hooks/deny-out-of-scope-write.sh`가 `baro-ai/`·`.claude/` 밖 Write/Edit을 exit 2로 차단한다(fail-closed). 이 훅이 막았다는 건 **"기술적으로 못 한다"가 아니라 "사용자 확인이 먼저"라는 신호**다 — Bash로 우회하지 않는다.
4. **다른 모듈 작업을 명시적으로 요청받으면** — 이 하네스의 baro-ai 전용 스택 규칙(ErrorCode 패턴, `{{테스트 명령}}` 등 `harness-map.md` 슬롯·스택 옵션)을 강제하지 않는다. 그 모듈의 실제 컨벤션을 코드에서 확인하고 따른다. §1~§6의 STOP(문서 정합·레거시 제거 등 범용 원칙)은 그대로 유효하다.

### 1. 문서·구현 정합

1. **문서·스펙·결정 vs 구현** — `{{스펙 저장소}}`(Approved), `{{결정 기록}}`(확정), `{{제품 범위}}`, `{{아키텍처 개요}}`, `{{배포 SSOT}}`와 다른 TTL·API 계약·enum·한도·env 이름·패키지 경로를 **조용히 맞추지 않는다**.
2. **문서 vs 문서** — PRD vs 스펙, 스펙 vs 와이어프레임, decisions vs architecture, 스펙 vs `.env.example` 등 **서로 다른 값·용어·경로**면 한쪽을 임의 선택하지 말고 충돌을 짧게 목록화해 확인 요청.
3. **임의 개선 금지** — "더 나은 기본값", "업계 일반값", "코드가 간단해짐"만으로 문서와 다른 수치·구조를 바꾸지 않는다. 변경 시 **문서 amend 또는 사용자 명시 승인**.
4. **불확실하면 질문** — 가정을 숨기지 않는다. 질문 없이 진행한 선택은 **잘못된 작업**.
5. **구현 상태 보고 전 코드 우선 확인** — 스펙 Must Have 체크박스(`[ ]`/`[x]`)·"미구현"·"대기 중"·"`#n` 선행 필요" 같은 서술은 기능이 merge된 뒤 스펙 동기화가 누락되면 stale해진다. 사용자·프론트에게 "이 API·enum·이벤트가 아직 구현 안 됨/트리거 안 됨"이라고 **부정적으로 단정**해 답하기 전에, 관련 Controller·Service(이벤트 발행부)·테스트를 직접 grep/Read로 확인한다. `{{스펙 저장소}}` 문구 하나만 근거로 구현 여부를 판단하지 않는다 — 필요하면 `gh issue view`로 실제 이슈 상태도 함께 확인.
6. **[스택 옵션: 생성 문서 검증]** **"생성 문서에 있다"를 소스 어노테이션으로 단정하지 않는다** — DTO·enum에 `@Schema`가 있다고 해서 Swagger에 실제로 노출된다고 단정하지 않는다. `@ApiResponse`에서 제네릭 wrapper(baro-ai는 `ResponseDto<T>`)를 `schema = @Schema(implementation = ResponseDto.class)`처럼 raw 타입으로 지정하면 springdoc이 실제 `data` 타입(리스트·필드·enum)을 못 읽어 스키마가 통째로 사라진다(`useReturnTypeSchema = true` 필요 — `openapi-conventions-operation.md` 참고). "프론트가 필요한 값이 Swagger에 이미 있다"고 답하기 전에 로컬 `/v3/api-docs`, 배포 서버 `/v3/api-docs`, 또는 `{{API 문서}}`을 실제로 열어 해당 스키마·enum이 진짜 노출되는지 확인한다.

**절대 금지:** 문서와 다른 API 필드, 에러 코드, env 키, 임계값을 임의 구현·커밋. **에러 코드 갱신을 “다음 커밋에” 미루기.** **스펙 문서만 보고 "미구현"이라고 사용자에게 보고 — 코드 미확인 상태로 구현 상태 단정.** **`@Schema` 존재만 보고 "Swagger에 이미 노출된다"고 보고 — 실제 생성된 OpenAPI 문서 미확인.**

### 2. ErrorCode · AOP/Interceptor — 같은 턴 즉시 갱신

API·BR 실패 케이스를 **추가·변경하면 같은 PR·같은 턴**에 끝낸다. “나중에” 금지.

| 변경 | 같은 턴에 필수 |
|------|----------------|
| 새 실패 분기·HTTP/`code` | `{Domain\|Feature}ErrorCode` + 도메인 예외 throw + **스펙 에러 표** + 응답 스키마 |
| 폐기된 `code`·게이트 | enum·throw·스펙·생성 문서 **삭제** (아래 레거시 절) |

> **[스택 옵션: 에러코드 enum 동시갱신]** baro-ai는 `SearchErrorCode`·`RecommendErrorCode` 패턴을 쓴다 (`harness-map.md` 스택 옵션). **권한·활동 어노테이션(AOP) 옵션은 꺼짐** — baro-ai에 `@Aspect`·커스텀 권한 어노테이션이 없고, 인증은 게이트웨이가 처리한다. 도입하면 `harness-map.md`에서 켜고 이 표에 행을 되살린다.

**금지:** throw/`code`만 넣고 enum·스펙 미갱신 · Draft 전용 코드를 Approved 전 enum에 미리 넣기 · Filter에서 envelope와 다른 ad-hoc JSON · HTTP로 나갈 경로가 없는 ErrorCode를 남겨 두기(`audits/cross-cutting/003` B-4)

SSOT: {{API 응답 규격}} · `spring-boot-java.md` ErrorCode 절

### 3. DB 스키마 — 마이그레이션 금지 (상용 보존 데이터 없음)

> **[스택 옵션: DB 마이그레이션 금지]** 이 절은 **운영 DB에 보존할 데이터가 없다**는 전제 위에 있다. 운영 데이터가 있는 프로젝트에서는 정반대가 맞으므로, `harness-map.md`에서 이 옵션을 끄고 이 절과 `deny-db-migration.sh` 훅을 함께 제거한다.

1. Flyway / Liquibase / `V*__*.sql` / 데이터 보존 마이그레이션 **작성·커밋 금지**.
2. 스키마 SSOT = **ORM 엔티티(최신 하나)** + 자동 DDL 반영 (`{{아키텍처 개요}}`).
3. 로컬·dev DB **폐기·재생성** 허용 (`docker compose down -v` 등). orphan·구 스키마 호환 레이어 금지.
   **단, 이 명령은 `deny-dangerous-bash.sh`가 의도적으로 차단한다** — 정책상 허용된다는 것과 에이전트가 스스로 실행해도 된다는 것은 다르다. 되돌릴 수 없는 삭제이므로 사람이 직접 실행한다. 훅에 막혔다면 우회하지 말고 사용자에게 실행을 요청한다.
4. “나중에 마이그레이션 도입” 식 예정 코드/파일·주석 추가 금지. prod 보존이 필요해지면 **그때** decisions + 마이그레이션 별도 결정.

### 4. 레거시·정책 불일치 코드 제거 (호환 레이어 금지 · **같은 변경에서 즉시**)

현행 Approved 스펙·BR·decisions·구현 계약과 다른 코드·경로·문서를 “호환용”으로 남기지 않는다.
**dev·상용 보존 데이터 없음** → 듀얼 패스·구 클라/DB 호환·orphan 유지 **불필요·금지**.

1. **삭제 대상:** 폐기 API/path · 정책상 폐기 enum/`ErrorCode`/필드 · 구 상수·검증(예: 대체된 730일 A1) · 대체된 Repository 메서드·벌크 쿼리 · 구 스키마 매핑 · 호환 if · `@Deprecated` 방치 · stale `@Schema`/메시지 · “나중에 지울” TODO · 스펙·OpenAPI의 **현행 계약으로 적힌** 구 수치·구 API명
2. **시점 (필수):** 정책 amend·경로 교체 구현과 **같은 커밋/같은 PR/같은 턴**. “다음 커밋에 정리”·“일단 새 경로만 추가” **금지**
3. **교체 = 구경로 삭제:** 새 구현을 넣으면 **호출되지 않는 구 메서드·상수·테스트 assert·문서 ‘현행’ 문구**를 같은 변경에서 제거. “요청 밖 dead code라서 언급만”으로 **넘기지 않는다** — 이번 변경이 대체한 코드는 **요청 범위**
4. **하지 않음:** 구 클라/DB 호환 어댑터 · orphan 컬럼 · deprecated 방치 · soft/hard·live/snapshot 등 **정책상 폐기된 이중 분기**
5. **예외 — 진짜 요청 밖:** 이번 정책과 **무관한** 기존 dead code만 언급. **정책 불일치·이번 교체 잔존은 이 절이 우선 → 삭제**
6. **이력 문서:** 스펙 Changelog·과거 체크리스트의 “당시 A1=730” 등은 OK. **‘현행 코드/계약’** 으로 적힌 구 값은 §1·본 절로 **즉시 amend**

### 5. API 계약 변경 — `Breaking-Change-Reason` 트레일러 (옵션 꺼짐 — 해당 없음)

> **[스택 옵션: OpenAPI 계약 보호]** `harness-map.md` 기준 baro-ai는 **꺼짐** — `oasdiff`·CI 계약 검증이 아직 없다. 이 절과 `warn-breaking-change.sh` 훅(현재 `settings.json`에 미등록)은 도입 후 다시 채운다.

### 6. 보안·아키텍처 성격 로직 변경 — `{{현재동작 요약}}` 같은 턴 갱신

인증·세션·토큰 저장 방식, 결제, 개인정보 저장·암호화, 그 외 "이게 바뀐 걸 사용자가 한참 뒤에야 알면 곤란한" 성격의 로직을 바꾸면, 그 작업과 **같은 턴**에 {{현재동작 요약}}의 해당 절도 쉬운 말로 고친다(없던 주제면 새 절 추가). "나중에 정리"·"스펙에 이미 적었으니 됐다" 금지 — ErrorCode·AOP(§2)와 동일한 패턴.

**대상(예):** 토큰·세션 저장 위치·전달 방식, 비밀번호·시크릿 처리, 결제 흐름, 대량 개인정보 접근·삭제 로직.

**금지:** `{{스펙 저장소}}`에만 적어두고 `how-it-works.md`는 방치 · "사소한 변경"이라며 임의로 갱신 생략 · 기술 용어를 그대로 옮겨적기(사용자가 다른 문서 없이도 읽히게 — `core-reporting.md` 준수).
